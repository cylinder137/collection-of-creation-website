# 激活码发售思路转变说明

> 记录 2026-09 起官网业务模式的**核心思路转变**：从「网页端在线发售激活码」转为「官网只做下载 + 桌面端驱动激活」。
> 本文面向团队成员与后续接入方（coBrain 等客户端），说明"为什么这么改、改了什么、现在怎么运作"。

---

## 一、背景：为什么必须转变

旧方案假设「用户在浏览器里完成：浏览产品 → 在线支付 → 提交机器码 → 拿到激活码 → 回软件里激活」。实践下来有几个根本性痛点，决定了它走不通：

| 痛点 | 具体表现 |
|---|---|
| **浏览器权限受限** | 网页 JS 无法稳定读取磁盘 / 系统级硬件指纹，机器码采集只能靠浏览器指纹 + File System Access API 兜底，弱、易变、跨浏览器不一致 |
| **机器码不可靠** | 旧算法混入浏览器特征，换个浏览器/清缓存机器码就变 → 激活码"换机失效"误判频发，售后爆炸 |
| **网页端验证不可信** | 网页端做的事在浏览器沙箱里都能被伪造/绕过，作为授权边界太脆弱 |
| **激活链路割裂** | 激活码签发、本地验签、产品启动校验要打通浏览器与桌面两端，实现散、维护难 |

**结论**：授权这件事**必须由运行在用户主机上的桌面程序（安装包/产品本体）主导**，网页只负责"把安装包递到用户手里"。桌面端可以用管理员权限自由读写文件、采集稳定机器码、做本地验签，浏览器做不到的这些限制，恰恰是我们要的——因为授权校验本就不该依赖浏览器。

---

## 二、新思路（目标架构）

一句话概括：**网页只做"下载门面"，授权完全由桌面端闭环。**

```
用户                         官网(网页)                    后端(zaowuji)            桌面端(exe/产品)
 │                             │                             │                        │
 │ ① 浏览/下载安装包 ─────────►│ 提供 exe 自解压包下载          │                        │
 │                             │（无购买、无激活、无支付入口）   │                        │
 │                             │                             │                        │
 │ ② 双击安装 ────────────────────────────────────────────────────────────►│ 采集机器码
 │                             │                             │                        │
 │ ③ 安装程序申请 admin 权限 ──────────────────────────────────────────────►│ 读文件/取机器码
 │                             │                             │                        │
 │ ④ 客户端下单 ─────────────────────────────────────────────►│ POST /orders         │
 │                             │                             │   (含产品ID+机器码+联系方式)│
 │                             │ ◄──────────────────────────│ 订单号                 │
 │                             │                             │                        │
 │ ⑤ 用户扫码转账(线下)        │                             │                        │
 │                             │  管理员在 /admin 人工核验收款 ──► PATCH 订单转已支付     │
 │                             │                             │                        │
 │ ⑥ 客户端提交机器码激活 ───────────────────────────────────►│ POST /activations     │
 │                             │                             │  RSA 私钥签发激活码     │
 │                             │ ◄──────────────────────────│  (绑定机器，换机失效)   │
 │                             │                             │                        │
 │ ⑦ 安装/每次启动验签 ◄─────────────────────────────────────│  本地验签 + 可选在线核验 │
```

设计要点：

1. **官网零售**：主页只展示产品 + 下载 exe 安装包，删除网页端购买页、激活页、在线支付、激活码展示。
2. **桌面端主导授权**：安装程序（管理员权限）与产品主程序共用**同一套机器码实现**，机器码 = `sha256(稳定硬件指纹)`，与浏览器/UI 层解耦。
3. **RSA 签名验签**：激活码由后端私钥签名，桌面端用内置公钥本地验签；绑定机器，换机/篡改即失效。
4. **激活双时机**：安装过程要激活码认证，产品每次启动也要激活码认证（本地验签 + 可选在线核验兜底吊销）。

> 详见 `docs/RSA与激活码接入文档.md` —— 面向 coBrain 客户端的完整接入规范。

## 三、落地到代码/接口

### 前端（front_end）
- 官网（`HomeView` / `OfficialLayout`）：公司介绍、产品下载卡片、四步激活流程引导、FAQ。**无任何购买/激活/支付入口**。
- 管理后台隐藏入口 `/admin`（`AdminLayout` + `AdminLoginView` + `AdminDashboardView`）：**官网无任何按钮/链接指向它**，仅能靠输入 URL `/admin` 直达。
- 管理后台功能：订单人工核验、激活码记录 + 吊销、产品管理与上下架。
- 删除：旧购买页 / 激活页 / 产品列表页 / 浏览器端机器码采集工具（`utils/device.ts`）。

### 后端（back_end）
- 管理端**无状态 RESTful 鉴权**：登录下发 HMAC 令牌，前端缓存（localStorage）；**每次管理操作请求都带身份，后端逐次回库核验**管理员存在且启用。
- 新增接口：
  - `GET/POST /admin/products`、`PUT /admin/products/{id}`、`PATCH /admin/products/{id}/status`（产品管理）
  - `POST /admin/licenses/{id}/revoke`（激活码吊销）
  - 订单人工核验：待审核（0）→ 已支付（1）
- 激活码签发：`POST /activations`，需已核验订单 + 机器码；订单终态后置为「已签发(4)」。
- RSA 公钥下发：`GET /api/license-key/public-key`；在线核验：`GET /api/license-key/verify`。

## 四、与旧方案的差异对照

| 维度 | 旧方案 | 新方案 |
|---|---|---|
| 官网职责 | 展示 + 在线发售激活码 | 展示 + 安装包下载（零售） |
| 激活发起方 | 浏览器 | 桌面端（exe/产品） |
| 机器码 | 浏览器指纹（易变、弱） | 硬件指纹 sha256（稳定、强），桌面端共用实现 |
| 权限 | 浏览器沙箱限制 | admin 权限自由读写文件/取指纹 |
| 支付 | 在线支付（未接通） | 线下转账 + 管理员人工核验 |
| 授权边界 | 网页侧验证（可被绕过） | RSA 本地验签（可靠） |
| 管理后台 | 入口可见 | `/admin` 隐藏直达，无任何页面入口 |
| 后台鉴权 | — | 无状态令牌，每次请求回库核验 |
