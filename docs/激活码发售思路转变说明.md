# 激活码发售思路转变说明

> 记录 2026-09 起官网业务模式的**核心思路转变**：从「网页端在线发售激活码」转为「官网只做安装包下载 + 桌面端驱动激活」。
> 本文面向团队成员与后续接入方（coBrain 等客户端），说明"为什么这么改、改了什么、现在怎么运作"。

---

## 一、背景：为什么必须转变

旧方案假设「用户在浏览器里完成：浏览产品 → 在线支付 → 提交机器码 → 拿到激活码 → 回软件里激活」。实践下来有几个根本性痛点，决定了它走不通：

| 痛点 | 具体表现 |
|---|---|
| **浏览器权限受限** | 网页 JS 无法稳定读取磁盘 / 系统级硬件指纹，机器码采集只能靠浏览器指纹 + File System Access API 兜底，弱、易变、跨浏览器不一致 |
| **机器码不可靠** | 旧算法混入浏览器特征，换个浏览器/清缓存机器码就变 → 激活码"换机失效"误判频发，售后爆炸 |
| **网页端验证不可信** | 网页端做的事在浏览器沙箱里都能被伪造/绕过，作为授权边界太脆弱 |
| **激活链路割裂** | 激活码签发、本地验签、产品启动校验要打通浏览器与桌面两端，实现散、维护难 |

**结论**：授权这件事**必须由运行在用户主机上的桌面程序（安装包/产品本体）主导**，网页只负责"把安装包递到用户手里"。

## 二、新思路：官网只下载，桌面端闭环授权

一句话概括：**网页只做"下载门面"，激活码的收款、签发、存储、校验全部由桌面端闭环完成。**

```
用户                         官网(网页)                    后端(zaowuji)            桌面端(exe 安装脚本/产品)
 │                             │                             │                        │
 │ ① 浏览/下载安装包 ─────────►│ 提供 exe 自解压包下载          │                        │
 │                             │（无购买、无激活、无支付入口）   │                        │
 │                             │                             │                        │
 │ ② 双击安装 ────────────────────────────────────────────────────────────►│ 请求管理员授权
 │                             │                             │                        │
 │ ③ 授权后自动采集机器码 ─────────────────────────────────────────────────►│ 读稳定硬件指纹
 │                             │                             │                        │  sha256(指纹)
 │                             │                             │                        │
 │ ④ 安装脚本调后端下单 ─────────────────────────────────────►│ POST /orders         │
 │                             │                             │  (产品ID+机器码+联系方式)│
 │                             │ ◄──────────────────────────│ 订单号 + 收款码图片     │
 │ ⑤ 界面展示收款码图片 ────────│                             │ ◄──────┐              │
 │    用户扫码转账(线下)        │                             │        │              │
 │                             │  管理员在 /admin 人工核验收款 ─► 订单转已支付          │
 │                             │                             │        │              │
 │ ⑥ 安装脚本提交机器码激活 ─────────────────────────────────►│ POST /activations     │
 │                             │                             │  RSA 私钥签发激活码     │
 │                             │ ◄──────────────────────────│  (绑定机器，换机失效)   │
 │                             │                             │        │              │
 │ ⑦ 激活码自动写入本地 ─────────────────────────────────────────────────►│ 存激活码文件
 │                             │                             │        │              │
 │ ⑧ 安装完成/每次启动本地验签 ◄──────────────────────────────│  内置公钥验签          │
```

### 为什么桌面端（exe）能解决浏览器解决不了的问题

1. **管理员授权 → 拿得到机器码**：安装包 exe 可向系统申请管理员权限运行，从而稳定读取硬件指纹（主板/硬盘/CPU 等），生成可靠机器码 `sha256(稳定硬件指纹)`。浏览器沙箱永远拿不到这个级别的主机身份。
2. **收款流程内嵌安装脚本**：安装过程中脚本自动调用后端订单接口，拿到订单号与**收款码图片**直接在安装界面展示，用户扫码转账即可，无需跳网页、无需手动记录订单号。
3. **激活码自动存储**：后端签发激活码后，桌面端把它自动写入本地文件/注册表，用户全程不用复制粘贴；产品每次启动自动读取并本地验签。
4. **授权边界可信**：验签用内置 RSA 公钥离线完成，绑定机器，换机/篡改即失效；浏览器端那套"可被伪造绕过"的校验整个移除。

## 三、落地到代码/接口

### 前端（front_end）
- 官网（`HomeView` / `OfficialLayout`）：公司介绍、产品下载卡片、四步激活流程引导、FAQ。**无任何购买/激活/支付入口**。
- 管理后台隐藏入口 `/admin`（`AdminLayout` + `AdminLoginView` + `AdminDashboardView`）：**官网无任何按钮/链接指向它**，仅能靠输入 URL `/admin` 直达。
- 管理后台功能：订单人工核验（待审核列表一键通过）、激活码记录 + 吊销、产品管理与上下架。
- 删除：旧购买页 / 激活页 / 产品列表页 / 浏览器端机器码采集工具（`utils/device.ts`）。

### 后端（back_end）
- 管理端**无状态 RESTful 鉴权**：登录下发 HMAC 令牌，前端缓存（localStorage）；**每次管理操作请求都带身份，后端逐次回库核验**管理员存在且启用。
- 订单接口（供桌面端调用）：
  - `POST /api/orders`：下单 → 返回订单号（桌面端据此展示收款码图片引导扫码）
  - `GET /api/orders/{orderNo}`：查询订单状态（桌面端轮询"已支付"后触发激活）
- 人工核验：`POST /api/admin/orders/{orderNo}/review-pass`，待审核（0）→ 已支付（1）
- 激活码签发：`POST /api/activations`，需已核验订单 + 机器码；签发成功订单置「已签发(4)」
- RSA 公钥下发：`GET /api/license-key/public-key`；在线核验：`GET /api/license-key/verify`
- 收款码图片：`front_end/public/image/`（网页静态目录，桌面端直接引用 `/image/wechat-qr.png` 等）

### 桌面端（coBrain 等客户端，待接入）
- 安装程序 + 主程序共用机器码采集（admin 权限取硬件指纹）
- 安装脚本内嵌：下单 → 展示收款码 → 轮询订单 → 提交机器码激活 → 自动存储激活码
- 内置 RSA 公钥，安装完成/每次启动本地验签

## 四、与旧方案的差异对照

| 维度 | 旧方案 | 新方案 |
|---|---|---|
| 官网职责 | 展示 + 在线发售激活码 | 展示 + 安装包下载（零售） |
| 激活发起方 | 浏览器 | 桌面端（exe 安装脚本/产品） |
| 机器码 | 浏览器指纹（易变、弱） | 硬件指纹 sha256（稳定、强），桌面端共用实现 |
| 权限 | 浏览器沙箱限制 | admin 权限自由读写文件/取指纹 |
| 支付 | 在线支付（未接通） | 安装脚本展示收款码 → 线下转账 → 管理员人工核验 |
| 激活码流转 | 网页展示，用户手动复制 | 后端签发 → 桌面端自动存储 |
| 授权边界 | 网页侧验证（可被绕过） | RSA 本地验签（可靠） |
| 管理后台 | 入口可见 | `/admin` 隐藏直达，无任何页面入口 |
| 后台鉴权 | — | 无状态令牌，每次请求回库核验 |
